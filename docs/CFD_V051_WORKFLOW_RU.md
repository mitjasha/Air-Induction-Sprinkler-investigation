# CFD v0.5.1 — проверяемая физика и автоматизированное исследование эжектора

Статус: Python-тесты пройдены; **новые расчётные случаи v0.5.1 ещё не проходили OpenFOAM v2606**. Точность, фазовая консервативность сохранённого MULES-потока и работоспособность новых `functionObject` подлежат проверке в WSL.

## Установленные результаты предыдущей v0.5 (не новая валидация)

- `coarse/open` / SST, около 60 мс: `airInlet` -6.5394e-6 м³/с, `k_phi` около 0.80156; расход стабилен после 20–25 мс.
- `coarse/closed` / SST, 60 мс: `airInlet` 0, `outlet` 8.27209e-6 м³/с; стабилизация выхода около 50–52 мс. Предыдущий анализатор ошибочно проверял `k_phi=0` вместо расхода outlet.
- Closed: в районе z≈25 мм резкое восстановление p_rgh (порядка 70 кПа на 20–30 мм), движение переходной области около 1.78 мм и пристеночной рециркуляции около 1.93 мм за 40–60 мс.
- В Closed наблюдались отрицательные относительные давления около -80 кПа, местами ниже. Если нулевой уровень p_rgh соответствует 101325 Па абсолютного, **несжимаемый воздух неприемлем для количественной оценки давления**. Это предупреждение, а не автоматическая поправка.
- Open сохранял приблизительно постоянный радиус водяного ядра ≈3.17 мм между z=10 и z=90 мм; **mixing shock не подтверждён**.
- Coarse y+ до примерно 164 на диафрагме. Текущая сетка не является проверенно пристеночно разрешённой.

## 1. Генерация — сохраняем версии и результаты раздельно

Обновлённая сетка **coarse не изменяется**, чтобы сохранить сравнимость с расчётами v0.5. Medium и Fine используют блоковую геометрическую градацию радиальных ячеек к стенке и осевых ячеек у диафрагмы/камеры подсоса. Важно: простой `simpleGrading` **не является локальной геометрической адаптацией и не гарантирует y+≈1**.

```bash
source /usr/lib/openfoam/openfoam2606/etc/bashrc
source .venv/bin/activate
python -m pytest -q
OUT="$HOME/CAE/CFD-runs/patent_v051"
python -m cfd.study_v05.generate --out-dir "$OUT"
python -m cfd.study_v05.batch --study-dir "$OUT" --cases ejector_coarse_open ejector_coarse_closed
```

Перед запуском обязательно `checkMesh`, `interFoam -dry-run`, и ручной просмотр `log.v05.dry`; дополнительный `waterInventory` должен успешно инициализироваться. Для Medium/Fine проведите отдельный `checkMesh` и `dry-run`, прежде чем запускать длинный расчёт. Не пересоздавайте старый каталог v0.5 — это уничтожит историю воспроизводимости.

## 2. Первый шаг — фазовый учёт

OpenFOAM.com VoF `createAlphaFluxes.H` использует MULES-перенос воды `alphaPhi10` и IO-имя `alphaPhi0.water` (`AUTO_WRITE` в близких версиях), но фактическое имя/сохранение в v2606 нужно подтвердить:

```bash
CASE="$OUT/ejector_coarse_open"
foamListTimes -case "$CASE" -latestTime
find "$CASE" -maxdepth 2 -name 'alphaPhi*' -print | head
```

Если `alphaPhi0.water` и `phi` существуют в **одной и той же временной директории**, после запуска расчёта:

```bash
python -m cfd.study_v05.phase_flux --case "$CASE" --report "$CASE/report"
```

Программа читает **значения на гранях**, суммирует ориентированные водяные потоки `alphaPhi0.water` и вычисляет газовый по `phi - alphaPhi0.water`. Получается кандидат `kQ_phase_boundary_candidate`; он не подменяется отношением смеси `k_phi`. Для настоящего теста сохранения массы воды дополнительно записывается `waterInventory: volIntegrate(alpha.water)`. Проверяем `(V_w(t2)-V_w(t1))/(t2-t1) + Σ_границы Φ_w ≈ 0` с учётом шага и запаздывания фазовых потоков.

Если отсутствуют поля, они бинарные/неконсистентны или инвентарный баланс не выполняется — **не публикуем консервативный kQ как подтверждённый**. Переход на сжимаемую модель изменит интерпретацию объёмных расходов газа: потребуется явное приведение к выбранным давлению и температуре.

## 3. Временная стабилизация Open и Closed

```bash
python -m cfd.study_v05.analyze --case "$CASE" --report "$CASE/report"
```

Для Open `flux_quasi_steady_observable=k_phi`; для Closed, где `k_phi=0` по условию стенки, проверяется ненулевой `outlet`. `ambientOpen` диагностируется отдельно. Эти оценки **не заменяют** проверку полей давления, доли воды и турбулентности.

## 4. Обработка пространственно-временных профилей

`pvpython` исполняется в отдельном окружении ParaView, не внутри Python `.venv`. Экспортируйте 3 продольные и 5 радиальных линий при одинаковых временных отметках. Пример для Closed:

```bash
PROJECT="$PWD"
CASE="$OUT/ejector_coarse_closed"
for MS in 40 42 44 46 48 50 52 54 56 58 60; do
  T="$(printf '0.%03d' "$MS")"
  pvpython "$PROJECT/cfd/study_v05/sample_pvpython.py" --case "$CASE" \
    --time "$T" --output "$CASE/profiles_t${MS}ms"
done
python -m cfd.study_v05.temporal \
  --profiles-dir "$CASE" --report "$CASE/temporal_report" --p-ref-abs 101325
```

Временной обработчик выдаёт `pressure_spacetime.png`, `transition_recirculation.png`, `temporal_metrics.csv`, `temporal_summary.json`. Положение 50%-восстановления определяется по `p(z)` между z=20–30 мм; конец рециркуляции по `U_z=0` у r=4.5 мм. Эти **эвристики** применимы к данной геометрии и НЕ доказывают существование двухфазного `mixing shock`.

## 5. Контроль давления и применимости газа

Из-за `g=0` поле `p_rgh=p`. На `outlet` и `ambientOpen` стоит `prghTotalPressure` с `p0=0` — это полное давление отсчёта, а не статическое по всей границе. Временной анализ оценивает `p_abs ≈ p_ref_abs + p_rgh` **только при явно принятой атмосферной привязке**; флаг включается при `p_abs / p_ref_abs < 0.8`. Это консервативный диагностический критерий, а не физический закон. При обнаруженных ~80–90 кПа разрежения нужна отдельно обоснованная **сжимаемая двухфазная постановка** и тест её корректности; **v0.5.1 остаётся incompressible interFoam**.

## 6. Контроль y+ и сетки

```bash
python -m cfd.study_v05.wall_qc --case "$CASE" --report "$CASE/report" --target-yplus 1
```

Получаем `wall_yplus.csv` и `wall_qc.json`; пустой `deflectorWall` исключается. Сообщение о превышении y+ не означает автоматическую неустойчивость, но **запрещает объявлять пограничный слой разрешённым**. Для каждого нового уровня сетки проверяем максимумы и распределение y+, включая области острой кромки, а также интерфейс, давление и расходы. Важно: `simpleGrading` — предварительная дешёвая версия сгущения, не замена boundary-layer mesh с контролируемой толщиной первой ячейки.

## 7. Программа дальнейших экспериментов и критерии приёмки

1. **Preflight v0.5.1:** `blockMesh`, `checkMesh`, `interFoam -dry-run` для Open/Closed, затем Medium/Fine. Исправить словари только в генераторе, повторить тесты.
2. **Кейс coarse Open/Closed:** независимые отчёты из новых прогонов, сравнить с контрольными v0.5; проверить отсутствие незаметного изменения постановки.
3. **Фазовый аудит:** `alphaPhi0.water`, `phi`, `waterInventory` и подписанные потоки на всех четырёх открытых патчах, контроль границ притока/оттока.
4. **Физика газа:** провести расчёт в подходящей сжимаемой модели, если абсолютное давление действительно падает до ~20 кПа или меньше; перепроверить граничные условия и режим насоса.
5. **Medium/Fine:** три сетки для одной физической модели; сравнить фазовые потоки, давление, положение перехода, радиус водяного ядра, y+, временную независимость. Не считать рост числа ячеек автоматической сходимостью.
6. **Турбулентность и интерфейс:** SST vs ламинарная и альтернативные модели; отследить разрешение интерфейса и чувствительность к численной диффузии/граничным условиям.
7. **Противодавление, диаметр и длина горловины, зазор, расход воды:** параметрические исследования и проверка возможного `mixing shock` по совместным признакам p, U, α и фазовых потоков.
8. **3D боковой воздухозаборник и дефлектор:** отдельные стадии после базовой верификации — 2D кольцевой вход не равен реальному боковому патрубку; моделирование свободной струи, плёнки и капель требует дополнительных моделей и экспериментов.
9. **Валидация:** сравнение с независимыми экспериментальными расходами воды и воздуха, давлением, геометрией и неопределённостью.
